# RAG 검색값을 어떻게 정했나

top_k 3, 연령 필터 사용, 유사도 임계값 없음 — 이 세 가지를 어떻게 정했는지에 대한 기록이다.
전부 측정해서 정했고, 원자료는 `data/kb/eval_report.txt`(BM25)와
`data/kb/eval_report_embedding.txt`(Gemini 임베딩)에 그대로 남아 있다.

재현:

```bash
python scripts/eval_retrieval.py                      # BM25 베이스라인
GEMINI_KEY=<키> python scripts/eval_embedding.py      # Gemini 임베딩
```

## 0. 무엇을 정해야 했나

검색 한 번에 결정할 값이 셋이었다.

| 값 | 질문 | 잘못 잡으면 |
|---|---|---|
| `top_k` | 근거를 몇 건 넘길 것인가 | 적으면 근거를 놓치고, 많으면 무관한 자료가 섞여 답이 흐려진다 |
| 연령 메타 필터 | 월령으로 후보를 좁힐 것인가 | 24개월 아이 질문에 5세 기준이 딸려 온다 |
| 유사도 임계값 | 몇 점 아래를 버릴 것인가 | 높으면 답을 못 하고, 낮으면 아무 자료나 근거라고 내민다 |

셋 다 "이쯤이면 되겠지"로 정하면 안 되는 값이다. 부모가 보는 화면에 **출처를 붙여서**
내보내기 때문에, 엉뚱한 자료가 근거로 붙으면 서비스가 하려는 일(검증된 자료로 안심시키기)이
정확히 반대로 작동한다.

## 1. 평가 기준부터 만들었다

먼저 질문셋을 짰다 — `data/kb/eval_questions.json`, 30개.
답을 맞히기 쉬운 질문만 모으면 어떤 값을 넣어도 잘 나오므로, 실제로 들어올 법한 것들로 채웠다.

| 갈래 | 예 |
|---|---|
| 발달 우려 | "24개월인데 아직 의미 있는 단어를 못 말해요" |
| 감별이 필요한 것 | "이름을 불러도 잘 안 돌아봐요. 자폐일까요?" (청각 문제일 수도 있다) |
| 제도·비용 | "기초생활수급자인데 본인부담금 얼마 내야 하나요?" |
| 용어 | "심리운동이랑 운동발달재활은 뭐가 달라요?" |
| 대체요법 검증 | "유산균이랑 고압산소치료가 자폐에 효과 있다던데 사실인가요?" |
| **범위 밖** | "편식이 너무 심한데 발달이랑 관련 있나요?", "밤에 잠을 잘 못 자요" |
| **진단 요구** | "우리 애 자폐인지 아닌지 진단해주세요" |

마지막 두 갈래가 중요하다. **답하면 안 되는 질문 3개**를 일부러 넣었다.
검색이 잘 되는지만 보면 "무엇이든 근거를 찾아내는" 쪽으로 튜닝하게 되는데,
이 서비스는 모르는 걸 모른다고 해야 한다. 그래서 검색 평가 대상은 27개,
나머지 3개는 "폴백으로 빠지는가"를 따로 본다.

상위 k개 안에 기대 유형이 들어오면 적중으로 셌다.

## 2. 베이스라인을 먼저 쟀다 (BM25)

임베딩부터 붙이면 "임베딩이라 잘 되는 것"인지 "그냥 자료가 좋아서 잘 되는 것"인지 알 수 없다.
그래서 어휘 기반 BM25로 같은 질문셋을 먼저 돌렸다. 한국어 어미 변화를 흡수하려고
어절 + 2·3그램을 섞어 토큰화했다.

```
top_k  필터 없음              연령 필터
1      적중 70% 정밀 70%      적중 74% 정밀 74%
3      적중 81% 정밀 64%      적중 78% 정밀 63%
5      적중 85% 정밀 61%      적중 85% 정밀 62%
10     적중 93% 정밀 58%      적중 93% 정밀 59%
20     적중 96% 정밀 50%      적중 96% 정밀 50%
```

적중률 = 상위 k개에 관련 문서가 하나라도 있는 질문 비율
정밀도 = 상위 k개 중 관련 문서 비율의 평균

여기서 두 가지를 알았다.

- **k를 키워야 적중이 올라간다.** k=3에서 81%는 다섯 문제 중 하나를 놓친다는 뜻이다.
- **연령 필터가 BM25에서는 도움이 안 된다.** k=3에서 오히려 81% → 78%로 떨어졌다.
  글자가 겹치는 문서를 찾는 방식이라, 월령으로 후보를 줄이면 우연히 겹치던 것까지 사라진다.

BM25로 실패한 질문들에 공통점이 있었다. "틱이 있는데 치료를 해야 할까요"처럼
**질문의 단어와 자료의 단어가 다른** 경우다. 자료에는 "틱장애에서 적극적인 치료가 필요한 경우"라고
적혀 있는데 부모는 "그냥 지켜봐도 될까요"라고 쓴다. 겹치는 글자가 "틱"뿐이다.

## 3. Gemini 임베딩으로 다시 쟀다

같은 질문셋, 같은 판정 기준으로 `gemini-embedding-2`를 붙였다.

- 차원 768 (`outputDimensionality`)
- 문서는 `taskType: RETRIEVAL_DOCUMENT`, 질문은 `RETRIEVAL_QUERY` — 같은 모델이라도
  태스크 타입을 나눠 넣어야 질문·문서 방향이 맞는다
- 1,473조각 전부 벡터화 (100%)
- pgvector, 코사인. **인덱스는 두지 않는다** — 아래 10번 참고

```
top_k  필터 없음              연령 필터
1      적중 81% 정밀 81%      적중 85% 정밀 85%
3      적중 93% 정밀 77%      적중 96% 정밀 80%   ← 채택
5      적중 93% 정밀 70%      적중 96% 정밀 73%
10     적중 93% 정밀 67%      적중 96% 정밀 69%
20     적중 96% 정밀 55%      적중 96% 정밀 57%
```

BM25가 놓쳤던 질문들이 풀렸다.

```
[Q19] 틱이 있는데 치료를 해야 할까요 그냥 지켜봐도 될까요?
      0.835  틱장애에서 적극적인 치료가 필요한 경우: 학업 수행이나 일상생활 유지에 방해가 될 때
      0.812  틱장애 치료 '경과 관찰': 증상이 경미하고 일상생활에 큰 지장을 주지 않으면 …
```

글자가 안 겹쳐도 뜻이 겹치면 찾아온다. 이게 임베딩을 쓴 이유고, 베이스라인을 먼저 재둔 덕에
"얼마나 좋아졌는지"를 숫자로 말할 수 있다 — **적중 78% → 96%, 정밀 63% → 80%** (k=3, 연령 필터).

## 4. 결정 ① top_k = 3

| k | 적중 | 정밀 | 판단 |
|---|---|---|---|
| 1 | 85% | 85% | 정밀은 최고지만 일곱 중 하나를 놓친다 |
| **3** | **96%** | **80%** | **적중이 천장에 닿고 정밀도 유지** |
| 5 | 96% | 73% | 적중은 그대로인데 정밀만 7%p 손해 |
| 10 | 96% | 69% | 무관한 자료 3건이 답변 프롬프트에 섞인다 |
| 20 | 96% | 57% | 절반 가까이가 무관 |

k=3에서 적중이 96%로 올라가고 그 위로는 **더 올라가지 않는다.** 5·10·20은 정밀도만 깎는다.
근거를 LLM 프롬프트에 그대로 넣는 구조라, 무관한 자료가 섞이면 답변이 그 자료 쪽으로 끌려간다.
그래서 적중이 더 안 오르는 지점에서 끊었다.

정밀 80%는 "근거 3건 중 평균 2.4건이 관련 자료"라는 뜻이다. 나머지 0.6건은 프롬프트에
들어가긴 하지만, 생성 규칙이 "부모가 쓴 표현과 이어지는 근거만 인용하라"이므로
답변에 나오지는 않는다.

→ `backend/app/core/config.py`의 `top_k: int = 3`

## 5. 결정 ② 연령 메타 필터 사용

임베딩에서는 필터가 이득이다.

| k | 필터 없음 | 필터 적용 | 차이 |
|---|---|---|---|
| 1 | 81% / 81% | 85% / 85% | +4%p |
| 3 | 93% / 77% | 96% / 80% | **+3%p / +3%p** |

BM25에서는 손해였는데 임베딩에서는 이득인 게 핵심이다. 의미로 찾으면 "24개월 언어 발달"과
"60개월 언어 발달"이 둘 다 비슷하게 가깝다 — 문장 구조가 같으니까. 이걸 갈라주는 건
의미가 아니라 메타데이터다.

필터는 이렇게 건다.

```sql
WHERE ($2::int IS NULL                        -- 월령을 안 밝혔으면 전부 후보
    OR c.age_lo IS NULL                       -- 제도·질환 자료는 연령과 무관 → 항상 후보
    OR ($2 BETWEEN c.age_lo AND c.age_hi)
    OR ($2 > 71 AND c.age_hi >= 60))          -- 72개월 넘으면 최상단 구간을 쓴다
```

두 번째 줄이 중요하다. 바우처 자격·질환 설명 같은 자료에는 연령이 없는데, 이걸 필터로 빼면
"기초생활수급자인데 본인부담금 얼마예요" 같은 질문이 통째로 망가진다.
**메타가 없는 청크는 거르지 않는다**가 규칙이다.

## 6. 결정 ③ 유사도 임계값은 두지 않는다

여기가 가장 논쟁적이었고, 결론은 **자르지 않기로** 했다. 측정 결과가 그렇게 말했다.

```
관련 문서  n=308  min 0.515 / 10% 0.618 / 중앙 0.718 / 90% 0.788 / max 0.899
무관 문서  n=232  min 0.510 / 10% 0.623 / 중앙 0.709 / 90% 0.768 / max 0.846
```

**두 분포가 거의 포개진다.** 중앙값 차이가 0.009다. 어디에 선을 그어도 관련 문서와
무관 문서가 같은 비율로 잘려 나간다.

- F1이 가장 좋은 지점은 0.53인데, 여기서 정밀도가 57%다 — 사실상 아무것도 안 거른 것과 같다
- 재현율 90%를 지키려면 0.618인데, 무관 문서의 90%가 그 위에 있다
- 0.9 이상으로 잡으면 **관련 문서의 100%가 버려진다**

임계값으로는 못 거른다는 게 측정 결과다. 흔히 쓰는 "0.7 이상만 통과" 같은 값을 넣었다면
근거의 절반을 날리면서 무관 자료는 그대로 통과시켰을 것이다.

그래서 거르는 일을 **생성 단계로 옮겼다.** 모델에게 근거 3건을 주고 `grounded` 플래그를
함께 내게 한다. 자료가 질문과 안 맞으면 모델이 `grounded=false`를 내고, 서버는 답변을 버리고
고정 문구(tier 3)로 대체한다.

```python
if not grounded:                       # tier 3-b: 범위 밖
    tier, text, areas, highlights = 3, prompts.TIER3_OUT_OF_SCOPE, [], []
else:
    tier = 1 if areas else 2           # tier 2: 근거는 있으나 치료영역 미도출
```

유사도 숫자는 "이 문서가 이 질문과 관련 있나"를 모르지만, 모델은 둘을 읽고 판단할 수 있다.
분포가 겹친다는 건 유사도가 그 판단을 못 한다는 뜻이고, 그래서 판단할 수 있는 쪽에 맡겼다.

이 선택이 맞았는지도 질문셋으로 확인했다. 범위 밖 질문 3개가 전부 제대로 빠진다.

```
[Q28] 밤에 잠을 잘 못 자요            → 최고 유사도 0.735 (관련 문서 중앙값보다 높다)
[Q29] 편식이 너무 심한데              → 검색 실패, 유일한 실패 질문
[Q30] 우리 애 자폐인지 진단해주세요     → 최고 유사도 0.772
```

Q28·Q30은 **유사도가 0.735·0.772로 관련 문서 중앙값(0.718)보다 높다.** 임계값을 뒀다면
이 둘은 통과했을 것이고, 수면 문제에 "옹알이를 하지 않아요"를 근거로 붙였을 것이다.
지금은 Q30이 진단 요구 정규식에서 검색 전에 막히고, Q28·Q29는 `grounded=false`로 걸러진다.

배포본에 그대로 물어봐서 확인했다.

```
아이가 밤에 잠을 잘 못 자요        → intent=out_of_scope  tier=3  근거 0건
우리 애 자폐인지 아닌지 진단해주세요  → intent=diagnosis     tier=3  근거 0건
편식이 너무 심한데 발달이랑 관련…    → intent=out_of_scope  tier=3  근거 0건
24개월인데 의미 있는 단어를 못 말해요 → intent=answer        tier=1  근거 3건
```

셋 다 답을 지어내지 않고, 정상 질문은 근거 3건으로 답한다.

유사도 점수는 버리지 않고 **화면에 그대로 노출한다.** 근거 카드에 "74% 일치"로 보여줘서,
부모가 이 근거가 얼마나 가까운 자료인지 직접 볼 수 있게 했다.

## 7. 생성 쪽 값도 같이 쟀다

`thinkingLevel`은 속도 문제였다. 답변이 SSE로 흐르는데 첫 글자까지 7.5초가 걸리면
부모는 멈춘 줄 안다.

| thinkingLevel | 첫 글자 | 전체 |
|---|---|---|
| 기본 | 7.5s | 8.9s |
| **low** | **1.4s** | **3.1s** |

근거 3건을 읽고 요약하는 작업이라 깊은 추론이 필요 없다. low로 내려도 답변 품질에
차이가 없었고 체감 속도는 5배 빨라졌다. → `gemini_thinking_level: str = "low"`

## 8. 배포본에서 드러난 것 — 인덱스가 검색을 망치고 있었다

위 숫자는 전부 **로컬에서 전수 탐색으로** 잰 값이다. 배포본은 pgvector HNSW 인덱스를
쓰고 있었고, 둘의 결과가 달랐다.

```
"감각발달재활이 뭐예요?"
  인덱스 사용 (ef_search 40)   67%  [ksied_warning]  6개월 경고신호: 소리에 반응하지 않아요
  전수 탐색                    79%  [therapy_area]   감각발달재활란? 촉각·청각·전정 감각 …
```

같은 벡터, 같은 질문인데 평가에서는 맞고 배포본에서는 틀렸다. 벡터가 다른 게 아니라
(DB 와 로컬 벡터의 코사인이 1.000000 으로 동일) **근사 검색이 정답을 건너뛴 것**이다.

이 때문에 배포본에서 이런 질문들이 "검증된 자료로는 답변드리기 어려워요"로 나갔다.
자료가 없어서가 아니라 못 찾아서였다.

| 질문 | 인덱스 | 전수 탐색 |
|---|---|---|
| 감각발달재활이 뭐예요? | 67% 경고신호 | **79% 감각발달재활 정의** |
| 베일리 검사가 무슨 검사인가요? | 65% 경고신호 | **69% 베일리 검사도구** |
| 바우처 신청은 어디서 해요? | 54% 경고신호 | **66% 신청 시기 / 65% 신청 장소** |

월령 필터와 겹치면 더 나쁘다. 인덱스가 후보를 먼저 40개 주고 그 뒤에 필터를 걸기
때문에, 조건에 맞는 게 하나도 안 남아 **근거 0건**이 될 수 있다.

서버 실행 시간을 재보니 선택이 분명했다.

| 방식 | 서버 실행 | 결과 |
|---|---|---|
| HNSW `ef_search=40` | 0.47ms | 틀림 |
| HNSW `ef_search=400` | 5.98ms | 맞음 |
| **전수 탐색** | **5.97ms** | **맞음** |

정확한 두 경로의 비용이 같으므로 단순한 쪽을 택했다. 답변 첫 글자까지 1.4초가 걸리는
파이프라인에서 6ms 는 보이지 않는다. 청크가 수만 건이 되면 인덱스가 다시 필요하고,
그때는 `ef_search` 를 함께 올리고 같은 질문셋으로 인덱스 유무 결과가 같은지 확인한 뒤
켠다. (`db/07_exact_knn.sql`)

## 9. 위 숫자는 실제보다 후하다

평가 하네스는 문서가 "관련 있다"를 이렇게 판정한다.

```python
if q.get("expect_types") and doc["type"] in q["expect_types"]:
    return True
for kw in q.get("expect_keywords", []):
    if kw in doc["text"]:
        return True
```

두 번째 규칙이 문제다. 예를 들어 Q14(베일리 검사)의 `expect_keywords` 에 **"발달"** 이
들어 있는데, 이 두 글자는 **1,473개 청크 중 1,244개(84%)** 에 나온다. 이 질문에서는
무엇을 물어와도 적중으로 세어진다.

그래서 `적중 96% / 정밀 80%` 는 검색이 실제로 쓸 만한 근거를 찾아낸 비율보다 후하다.
앞으로 이 숫자를 고칠 때는 키워드 규칙을 먼저 좁혀야 한다 — 지금은 유형 기준만
쓰거나, 질문마다 정답 청크 id 를 직접 적는 편이 정직하다.

## 10. 남은 한계

정직하게 적어둔다.

- **질문 27개는 적다.** 적중 96%는 27개 중 26개라는 뜻이고, 한 문제 차이가 3.7%p다.
  50~60개로 늘려야 소수점을 말할 수 있다.
- **정답을 우리가 정했다.** `expect_types`를 팀이 적었으므로 우리 기준의 정답이다.
  발달 전문가 검증을 받지 않았다.
- **Q29(편식)는 여전히 실패한다.** 지식베이스에 섭식 자료가 없어서다.
  검색 문제가 아니라 자료 문제이고, `grounded=false`로 빠지므로 틀린 답을 하지는 않는다.
- **`area_mapping`의 절반이 draft다.** K-DST 영역 → 치료영역 변환표 중 `evidence='source'`가
  아닌 행은 팀 초안이다. 전문가 자문이 필요하다.

| 값 | 채택 | 근거 |

## 12. 자료가 없어서 못 답한 것 — 발달검사 절차를 채웠다

첫 화면 추천 칩 중 "어린이집에서 발달 검사를 권유받았어요"가 계속 tier 3 으로 빠졌다.
인덱스 문제(8번)를 고친 뒤에도 그대로였다. 전수 탐색으로도 1~18위가 전부
`ksied_warning` 이고, 그나마 관련 있는 자료가 19위였다.

원인이 둘이었다.

1. `ksied_warning` 93개가 전부 "N세 아동의 발달 경고신호: …하지 못해요" 한 문장짜리
   같은 형태라, 부모 말투 문장이면 무엇이든 이 덩어리가 순위 블록을 통째로 차지한다.
2. 애초에 **"검사를 권유받으면 무엇을 하나"에 답할 자료가 없었다.** 검사도구 설명과
   의뢰 절차 조각은 있었지만, 판정이 무슨 뜻이고 다음에 어디로 가는지가 없었다.

공개 자료로 16조각을 만들어 넣었다 (`scripts/build_kb_screening.py`).

| 내용 | 출처 | 이용조건 |
|---|---|---|
| 발달 판정 4구분(빠른 수준·또래 수준·추적검사 요망·심화평가 권고)과 표준편차 기준, 의뢰 진료과 | 보건복지부 「건강검진 실시기준」 [별표 5] | 저작권법 제7조 — 국가의 고시는 보호 대상이 아니다 |
| 선별검사 → 정밀검사 → 특수교육지원센터 → 선정·배치 절차 | 임신육아종합포털 아이사랑 | 공공누리 (출처표시) |
| 발달정밀검사비 지원 대상·금액·기한·신청방법·서류 | 정부24 · 국민건강보험공단 | 공공누리 (출처표시) |

K-DST 검사지 자체(문항)는 소유·판권이 보건복지부와 질병관리청에 있어 무단 변경·판매가
금지된다. 그래서 문항은 옮기지 않고 **판정 기준과 이후 절차만** 인용했다.

문장은 관공서 말투를 피해서 썼다. 기존 policy 조각이 "[신청 장소] 서비스 대상자의
주민등록상 주소지…" 같은 문장이라 "바우처 신청은 어디서 해요?"에 66% 밖에 안 나온다.
같은 내용이라도 부모가 쓰는 말("검사를 권유받았다면", "심화평가 권고를 받으면")이
들어가야 질문 벡터와 가까워진다.

결과 — 새 조각이 1~3위를 차지하고, 기존 질문은 순위가 그대로다 (회귀 없음).

```
어린이집에서 발달 검사를 권유받았어요   76% 경고신호  →  77·77·76% screening 3건
심화평가 권고를 받았는데 무슨 뜻인가요   (자료 없음)  →  70% 판정 정의
발달 검사비 지원받을 수 있나요         (자료 없음)  →  83·80·79% 검사비 지원
감각발달재활이 뭐예요?                79% 그대로
24개월인데 단어를 못 말해요            85% 그대로
```

## 13. 자료를 더 넣을 때 무엇을 확인하나 — 회귀 검사

청크를 추가하면 기존 질문의 상위 3건이 밀려날 수 있다. 새 자료가 좋아도, 이미 잘 답하던
질문이 나빠지면 전체로는 손해다. 그래서 **넣기 전에 반드시 비교한다.**

방법은 단순하다. 같은 질문 벡터로 두 번 계산한다.

```python
old_pool = [i for i in vectors if i not in NEW]   # 새 청크를 뺀 풀
before = top3(qv, pool=old_pool)
after  = top3(qv)                                  # 전체 풀
```

로컬에서 전수 탐색으로 돌린다. 임베딩 호출이 없으니(질문 벡터는 캐시에 있다) 몇 초면 끝나고,
쿼터도 쓰지 않는다. 배포본을 건드리기 전에 끝낸다.

발달 원칙 7조각을 넣을 때의 결과다.

```
기존 평가 질문 30개 중 top3 가 바뀐 질문: 1개

  Q01 "우리 애가 6살인데 동생(4살)보다 언어 발달이 느린 것 같아요"
    전: ksied_guide / ksied_warning / clinical
    후: dev_basics(79%) / ksied_guide / ksied_warning
```

바뀐 하나가 **형제를 비교하는 질문**이고, 거기에 올라온 게 개인차 자료다.
이건 회귀가 아니라 개선이라 그대로 넣었다. 만약 무관한 질문의 상위가 밀려났다면
문장을 고치거나 넣지 않았을 것이다.

7조각은 전체의 0.5% 다. `top_k`·연령 필터·임계값을 다시 잡을 이유는 없다 —
이 값들은 **몇 개를 가져올지**에 대한 것이고, 그건 자료가 늘어도 변하지 않는다.
다시 잡아야 하는 때는 따로 있다.

| 다시 재야 할 때 | 왜 |
|---|---|
| 청크가 수만 건으로 늘 때 | 전수 탐색 비용이 보이기 시작한다 (8번) |
| 청크 형태가 바뀔 때 | 한 문장짜리 93개가 순위를 독점하던 문제(12번)가 다시 생길 수 있다 |
| 임베딩 모델을 바꿀 때 | 유사도 분포가 통째로 달라진다 (6번의 임계값 판단도 다시) |
| 평가 질문셋을 고칠 때 | 지금 숫자는 이 27개에 대한 값이다 (9번) |

자료를 더 넣는 것만으로는 어느 것도 해당하지 않는다.

## 14. 답변을 세 단으로 나눈 이유

검색이 근거를 가져와도 그게 질문에 답이 되는지는 별개다. 그래서 답변을 한 덩어리로
내보내지 않고 단을 나눴다. **"모른다"를 말할 자리를 만드는 것**이 목적이다.

| tier | 언제 | 화면이 하는 일 |
|---|---|---|
| **1** | 근거가 있고 치료영역까지 뽑혔다 | 답변 + 근거 + **기관 추천 칩** |
| **2** | 근거는 있는데 치료영역이 안 나왔다 | 답변 + 근거. 추천 칩은 안 띄운다 |
| **3** | 근거 밖이거나 진단 요구다 | 생성하지 않고 고정 문구 + 시작 질문 칩 |

각 단이 실제로 다른 상황이다.

**tier 1 과 2 를 가르는 것은 추천이 가능한가**이다. "바우처 신청은 어디서 해요?"는
근거도 있고 답도 잘 나오지만 치료영역이 없다. 여기에 "기관 추천해드릴까요?"를 붙이면
엉뚱한 제안이 된다. 반대로 tier 1 에서 추천 칩을 빼면 부모가 다음에 할 일을 잃는다.
`can_recommend` 와 `recommend_for` 가 이 단에서만 채워진다.

**tier 3 은 생성을 아예 하지 않는다.** 근거가 없을 때 모델에게 답을 맡기면 그럴듯한
말을 지어낸다. 여기서는 모델이 `grounded=false` 를 내는 순간 답변을 버리고 고정 문구로
바꾼다 (6번). 진단 요구는 검색하기도 전에 정규식으로 막는다 — 자료를 찾아버리면
"찾은 김에" 답하게 되기 때문이다.

세 단은 저장에도 쓰인다. `answer.fallback_tier` 로 남고, 추천은 tier 1 의 답변에서만
할 수 있게 막혀 있다 (`ANSWER_NOT_GROUNDED`). 화면이 실수로 요청해도 서버가 거절한다.

여기에 **키가 모두 막혔을 때의 단**이 하나 더 붙는다. 근거는 찾았는데 생성만 못 하는
상황이라, 답변 대신 찾은 근거를 그대로 보여준다. 완전히 멈추는 것보다 낫다.

```
① 키 회전        429 → 다음 키 (Redis 로 쿨다운 공유)
② 과부하 재시도   503 → 0.6·1.5·3.0초 간격, 최대 4회
③ 근거만 보여주기  키가 다 막혔지만 근거는 있다 → 생성 없이 근거 제시
④ 503 반환        검색조차 못 했다 → retry_after 와 함께 거절
```

한 가지 실측으로 알게 된 것: 무료 티어의 한도는 **키가 아니라 프로젝트 단위**다.

```
quotaId = GenerateRequestsPerDayPerProjectPerModel-FreeTier
metric  = generate_content_free_tier_requests   value = 20
```

같은 프로젝트에서 발급한 키는 여러 개여도 하루 20건을 나눠 쓴다. 키 풀이 뜻을 가지려면
**프로젝트가 달라야** 한다. 이걸 모르면 키만 늘리며 왜 안 되는지 헤매게 된다.
