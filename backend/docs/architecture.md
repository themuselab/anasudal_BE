# 안아수달은 어떻게 만들어졌나

인프라에서 시작해 질문 하나가 답이 되기까지, 그리고 👍👎 하나가 어디에 쌓이는지까지.
값을 어떻게 정했는지는 [rag-tuning.md](./rag-tuning.md)에 따로 있다.

---

## 1. 인프라 — 왜 이 모양인가

```
       인터넷
          │  HTTP :80
   ┌──────▼──────────────────────────────────┐
   │  EC2 게이트웨이 (퍼블릭 서브넷)              │
   │    nginx → ECS 태스크 (network_mode=host) │
   │    Postgres 16 + pgvector  (127.0.0.1)   │
   │    Redis                    (127.0.0.1)  │
   └──────▲──────────────────────────────────┘
          │ SSM Session Manager (SSH 포트 없음)
       운영자
```

한 대에 다 올렸다. 작은 서비스에 RDS·ElastiCache를 따로 두면 비용과 네트워크 복잡도가
서비스 자체보다 커진다. DB와 Redis는 `127.0.0.1` 에만 바인딩돼 밖에서는 어떤 경로로도
닿지 않고, 운영자는 SSM 포트포워딩으로만 들어간다. **SSH 포트를 열지 않는다** —
키 관리도, 브루트포스 걱정도 없다.

| 조각 | 무엇 |
|---|---|
| ECR | 이미지 저장소 |
| ECS on EC2 | `network_mode = "host"` — 태스크가 호스트의 localhost 를 그대로 쓴다 |
| SSM Parameter Store | DB 접속 문자열·Gemini 키. 컨테이너 시작 시 주입된다 |
| Terraform | VPC·보안그룹·IAM·ECR·ECS·SSM 전부 코드로 |
| GitHub Actions + OIDC | `main` 푸시 → 이미지 빌드 → 태스크 정의 갱신 → 서비스 배포 (~3분) |

배포 계정은 이 프로젝트만 만질 수 있는 IAM 사용자다. 계정에 있던 다른 프로젝트와는
네트워크·이름·권한 세 겹으로 갈라뒀다 ([infra/README.md](../../infra/README.md)).

**주의할 점 하나**: SSM 파라미터를 바꿔도 돌고 있는 컨테이너에는 반영되지 않는다.
환경변수는 시작할 때 주입되므로 `aws ecs update-service --force-new-deployment` 가 필요하다.
Gemini 키를 추가하고 왜 안 붙는지 헤매기 쉬운 지점이다.

## 2. 데이터 두 갈래

서비스가 답할 수 있는 건 결국 가진 자료만큼이다. 두 갈래를 따로 모았다.

**기관 2,866곳** — 발달재활서비스 가격공시(broso)가 뼈대다. 사업자등록번호가 PK고,
주소·전화·좌표·홈페이지·운영시간은 카카오 로컬 API와 플레이스에서 채웠다.
치료영역별 단가는 공시 그대로다.

```
주소 93.2% · 전화 93.6% · 좌표 95.3% · 카카오맵 81.8% · 홈페이지 45.7% · 운영시간 34.5%
```

**지식 1,496조각** — 전부 국가기관·공공 출처다.

| 출처 | 조각 | 이용조건 |
|---|---|---|
| 질병관리청·보건복지부 K-DST | 736 | 검사지 문항은 옮기지 않고 기준만 |
| 삼성복지재단·육아정책연구소 새싹과단비 | 402 | 2차 인용 포함 — 공개 재배포 전 확인 필요 |
| 질병관리청 국가건강정보포털 | 310 | **공공누리 4유형 — 상업적 이용 금지** |
| 보건복지부 전자바우처 사업안내 | 27 | |
| 보건복지부 별표5 · 아이사랑 · 정부24 | 16 | 고시는 저작권 대상 아님 / 공공누리 |
| 안아수달 자체 매핑 초안 | 5 | 전문가 검증 전 |

국가건강정보포털 몫이 상업적 이용 금지라, 제품화한다면 별도 문의가 필요하다.
지금 단계에서는 문제없지만 나중에 발목을 잡을 수 있어 적어둔다.

## 3. 질문 하나가 답이 되기까지

```
질문
 │
 ├─ ① 게이트 (정규식)      진단 요구 → 검색 전에 차단
 │                        인사·서비스 문의 → 소개 문구
 │                        "같이 살펴볼까요?" → 관찰 화면
 │                        "추천해줘" → 지역 묻기 또는 추천
 │
 ├─ ② 월령 추출·저장       "30개월" → 세션에 남긴다
 │
 ├─ ③ 검색                질문 임베딩(768d) → 연령 필터 → 코사인 전수 탐색 → 상위 3건
 │
 ├─ ④ 생성                근거 3건만 주고 JSON 강제. grounded 플래그를 함께 받는다
 │
 ├─ ⑤ 단 판정              grounded=false → tier 3 (고정 문구)
 │                        치료영역 있음 → tier 1, 없음 → tier 2
 │
 └─ ⑥ 저장                원문 없이 영역 코드·키워드·40자 요약만
```

**① 게이트를 검색 앞에 둔 이유.** "우리 애 자폐인지 진단해주세요"를 검색하면 자폐 자료가
잘 나온다. 자료가 있으면 모델은 답하려 든다. 그래서 찾기 전에 막는다.
유사도로는 못 거른다 — 측정해보니 이런 질문의 최고 유사도가 0.772 로 관련 문서
중앙값(0.718)보다 높았다.

**③ 검색에 인덱스를 쓰지 않는다.** HNSW 가 기본 설정에서 정답을 놓쳤다. 1,496행에서는
전수 탐색이 5.97ms 로 고품질 HNSW(5.98ms)와 같으면서 결과가 항상 정확하다.
자세한 경위는 rag-tuning 8번.

**④ 근거를 3건만 준다.** 더 주면 무관한 자료가 섞여 답이 그쪽으로 끌려간다.
k=3 에서 적중이 천장에 닿고 그 위로는 정밀도만 깎인다.

**⑥ 원문을 저장하지 않는다.** `answer` 테이블에 질문 원문·답변 원문 열이 의도적으로 없다.
남는 건 치료영역 코드, 키워드 명사 몇 개, 그리고 별도 키로 만든 40자 요약뿐이다.

답변은 SSE 로 흘러간다. `meta`(근거 건수) → `delta`(글자) → `done`(볼드까지 반영된 최종본).
첫 글자까지 1.4초다 — `thinkingLevel: low` 로 7.5초에서 줄였다.

## 4. 같이 살펴보기 — 검색을 타지 않는 갈래

18~48개월 아이를 대상으로 부모가 집에서 해보는 상호작용 과제다. 과제·대사·선택지는
표(`screening_task` / `_step` / `_option`)에서 나오고 임베딩도 검색도 거치지 않는다.
API 도 `/v2` 로 따로 뒀다 — 쓰임과 수명이 v1 과 다르다.

**판정하지 않는다.** 근거 논문에서 과제 성공·실패만 쓴 모델은 AUROC 0.76 이고, 그것도
"고위험 vs 확진"을 가르는 2단계 과제였다. 자주 인용되는 0.93 은 SRS 설문 텍스트를 함께
넣은 값이고 그 설문은 라이선스가 있어 쓸 수 없다. 우리에겐 그 약한 조각 하나뿐이라
위험도 3단계를 내면 근거보다 강한 확신을 표현하게 된다. 그래서 결과는 기록이고
판단은 전문기관이 한다.

기록에 남는 것: 월령, 응답 번호, 건너뛴 과제, 영역 태그. **아이 이름은 받지 않는다.**
링크가 곧 열쇠라 토큰은 uuid v4, 180일 만료, 본인 삭제 가능, 응답에 `noindex`·`no-store`.

건너뛴 과제는 신호와 완전히 분리해 기록한다. 준비물이 있고 없고는 아이가 아니라 집
사정이라, 섞으면 형편이 어려운 집 아이가 불리해진다.

## 5. 👍👎 를 누르면 어디로 가나

```
화면에서 👍 또는 👎(+사유)
        │
        │  POST /v1/feedback { answer_id, rating, reason_code }
        ▼
   ① 검증        👎 인데 사유가 없으면 400 FEEDBACK_REASON_REQUIRED
                 사유 코드가 표에 없으면 400 INVALID_REASON_CODE
        ▼
   ② feedback    답변당 한 줄. 다시 누르면 덮어쓴다 (ON CONFLICT DO UPDATE)
        ▼
   ③ Redis 조회   key("conv", answer_id) → { answer, age }
                 답변 본문은 DB 에 없다. 세션 TTL(24h) 동안만 Redis 에 있다
        ▼
   ④ training_sample  눌린 답변만 학습 표본으로 옮긴다
```

`training_sample` 한 줄에 들어가는 것:

| 열 | 어디서 | 비고 |
|---|---|---|
| `rating`, `reason_code` | 방금 누른 값 | 👎 사유 3종 |
| `question_summary` | `answer.question_summary` | **원문이 아니라 40자 요약**. 전용 키로 백그라운드 생성 |
| `answer_text` | Redis `conv:<answer_id>` | 있을 때만. 24시간 지나면 비어 있다 |
| `child_age_months` | 세션 | |
| `fallback_tier` | `answer` | 어느 단의 답변이었나 |
| `extracted_areas`, `intent_keywords` | `answer` | 치료영역·키워드 |
| `evidence` | `answer_evidence` | 어떤 청크가 몇 위로 쓰였나 + 유사도 |
| `recommended` | `answer_recommendation` | 추천한 기관 사업자번호 |
| `model` | `answer` | 어느 모델이 만든 답인가 |

**왜 이렇게 모으나.** 나중에 이 표만 보면 "어떤 근거를 몇 위로 썼을 때 부모가 👎 했나"를
되짚을 수 있다. 검색이 문제였는지(엉뚱한 청크가 상위), 생성이 문제였는지(근거는 맞는데
답이 이상), 매핑이 문제였는지(영역이 틀림)를 가를 수 있는 최소한의 정보다.
👎 사유 3종(`MISMATCH` 요청한 내용이 아니에요 / `UNCLEAR` 이해하기 어려워요 /
`BAD_RECO` 기관 추천이 아쉬워요)이 그 세 갈래와 대략 맞물린다.

**개인정보는 여기에도 없다.** 질문 원문 대신 요약이고, 그 요약을 만드는 프롬프트가
이름·지역·기관명·전화번호를 빼도록 고정돼 있다. 답변 본문은 Redis 에 남아 있을 때만
따라온다 — 24시간이 지나 사라졌으면 나머지만 저장된다.

**답변당 한 줄이다.** 👍 눌렀다가 👎 로 바꾸면 덮어쓴다. 세션이 만료되면 `answer` 가
CASCADE 로 지워지지만 `training_sample` 은 남는다 — 학습용으로 모으는 것이 목적이라
세션 수명과 분리했다.

## 6. Redis 가 하는 일

없어도 서비스는 돌아간다. 다만 느려지고 쿼터를 더 쓴다.

| 쓰임 | 수명 | 없으면 |
|---|---|---|
| 질문 임베딩 캐시 | 7일 | 같은 질문마다 Gemini 호출 |
| 지역·기관 조회 캐시 | 10분 | 매번 DB |
| 추천 칩 회전 오프셋 | — | 무작위로 대체 |
| IP 시간당 질문 수 | 1시간 | 제한 없음 |
| 답변 본문 임시 보관 | 24시간 | 👍👎 해도 `answer_text` 가 빈 채로 저장 |
| **Gemini 키 쿨다운** | 키마다 | 태스크가 여러 개면 한도를 각자 다시 배운다 |

마지막이 중요하다. 429 를 맞은 키를 Redis 에 공유해두면 다른 태스크가 같은 키로 또
찔러보지 않는다.

## 7. 지금 알고 있는 한계

- **평가 질문 27개는 적다.** 적중 96% 는 27개 중 26개라는 뜻이고 한 문제가 3.7%p 다.
  게다가 판정 규칙이 후해서 실제보다 높게 나온다 (rag-tuning 9번).
- **`area_mapping` 의 절반이 초안이다.** K-DST 영역 → 치료영역 변환표에서
  `evidence='draft'` 인 행은 팀이 적은 것이다. 전문가 자문이 필요하다.
- **관찰 과제의 영역 태그도 초안이다.** 기관 필터에만 쓰고 판정에는 쓰지 않는다.
- **무료 티어는 하루 20건이다.** 그것도 키가 아니라 프로젝트 단위라, 같은 프로젝트에서
  키를 늘려도 한도는 그대로다.
- **국가건강정보포털 자료 310조각은 상업적 이용이 막혀 있다.**
